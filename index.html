座舱 Agent Harness 评测体系

聚焦 T/E/B/C/M/L 六维度，覆盖工具检索、执行质量、A/B 增量、上下文管理、记忆管理、时延拆解

01 边界 T 工具检索 E 执行质量 B A/B 增量 C 上下文 M 记忆 L 时延 附录

01 Harness 评测边界

判定口径：模型版本固定时，指标变化应主要来自 Harness 行为。正确工具未进入 Top-K → 归因工具检索；已进入 Top-K 但模型没选 → 归因模型；模型输出正确但执行顺序/重试/状态更新错了 → 归因 Harness 执行层。

纳入范围

• 工具目录检索：从 N 个工具召回 Top-K 候选的召回率、排序质量和检索时延
• 工具调用并行/串行调度正确性
• 工具调用失败时的恢复动作：retry / fallback / abort_gracefully
• 多个业务域的指令同时并发执行质量
• Harness 自身引入的额外响应时延
• 给下游传递的上下文/记忆信息完整性

不纳入范围

• 模型在 Top-K 候选中的最终选择
• 参数生成（填什么值）
• 意图分解（识别子意图）
• 歧义消解（主动追问）
• 全双工对话中的打断/误触发处理

T 工具检索

根据用户 prompt 从工具库 N 中召回 Top-K 候选工具，再让模型在候选工具中选择和填参。检索本身必须单独评测。

指标定义判定方式优先级
T-1Required Tool Recall@K — 任务真正需要的工具是否都出现在 Top-K 候选列表中Rule-basedP0
T-2Tool Ranking Quality — 正确工具的排序质量（MRR / nDCG@K），排序越靠前模型选错的概率越低Rule-basedP1
T-3Tool Retrieval Latency P95 — 检索步骤本身的时延，按工具库规模 N 分桶报告自动计时P0

E 执行质量（Execution）

通过 Mock Injection 将固定模型输出注入 Harness，观察执行层本身的并行/串行/恢复/正确性行为。

指标定义判定方式优先级
E-1Parallel Call Accuracy — 标记为 parallel 的工具是否真正并行发出（时间戳差值 ≤ 50ms）Rule-basedP0
E-2Serial Order Correctness — 有依赖关系的工具是否按正确顺序串行执行Rule-basedP0
E-3Tool Error Recovery Rate — 故障注入后 Harness 的恢复动作（retry/fallback/abort）是否符合预期LLM-as-JudgeP0
E-4Correctness — Harness 输出的工具调用 (name + args) 与 groundtruth 是否一致Rule-basedP0

B A/B 增量价值（Delta）

同一模型、同一批 case，加 Harness 后比 Baseline 好多少。公式永远是 Δ = Harness − Baseline。

指标定义判定方式优先级
B-1Task Success Rate Δ — Harness 组的任务成功率比 Baseline 组高多少Rule-basedP0
B-2pass^k Δ (k=3) — 同一条 case 连跑 k 次，k 次全成功才算稳定，比较两组的稳定性差异Rule-basedP0
B-3Cross-domain TSR Δ — 只看跨域 case（如空调+导航+音乐），再算一次 B-1 的增量Rule-basedP0
B-4E2E Latency Δ — Harness 组 vs Baseline 组的端到端耗时差值（变快或变慢）自动计时P0
B-5pass@k Δ — 同一条 case 各跑 k 次，至少 1 次成功即算通过，比较两组通过率差异（比 pass^k 更宽松的稳定性视角）Rule-basedP1

C 上下文管理（多轮对话）

同一会话内的短期上下文传递。Dim C 是同一会话内的上下文；Dim D 是跨会话的长期记忆。

指标定义判定方式优先级
C-1Context Injection Accuracy — 该传给下一轮的上下文字段，Harness 有没有真的传进去（JSON 字段等值比较）Rule-basedP0
C-2Context-dependent Turn Success — C-1 看「有没有传」，C-2 看「传了之后这一轮做对没有」Rule-basedP0
C-3Trajectory Completion Rate — 整条多轮任务是否从头到尾所有 checkpoint 都通过Rule / HybridP0

M 记忆管理（跨会话 Memory）

跨会话长期记忆的写入、归档、内容准确与跨会话召回注入。

指标定义判定方式优先级
M-1Memory Write Success — 记忆有没有成功落库（最低层存储可用性指标，不判断写得对不对）Rule-basedP0
M-2Memory Category Accuracy — 记忆写到了正确的归档维度里吗（location / preference / contact / safety）Rule-basedP0
M-3Memory Slot Accuracy — 写入的 key、value、scope 是否正确Rule / HybridP0
M-4Memory Recall & Injection Accuracy — 新会话中需要某 memory 时，Harness 有没有检索出来并注入 ContextRule-basedP0

L 时延拆解

时延是每次跑评测的副产品，不需要单独构造评测集。B-4 看端到端体验是否变快；本节进一步拆开看工具检索和执行前编排各耗时多少，以及并行调度节省了多少时间。

指标定义判定方式优先级
L-1Harness Overhead — 工具检索耗时 + 执行前编排耗时（解析+路由+调度），目标 P95 < 40msHarness 内部埋点P0
L-2Parallel Scheduling Gain — 串行理论总时延 − 并行实际时延，工具数越多收益越大计算推导P0
